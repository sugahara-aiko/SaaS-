# SaaS管理シート 自動化プロジェクト

社内SaaSツール管理スプレッドシートの再構成と月次チェック自動化のためのGoogle Apps Script(GAS)プロジェクトです。

## 全体ロードマップ

| ステップ | 内容 | 状態 |
|---|---|---|
| **Step 0** | シート構成の再構築(4シート分割・費用の数値化) | 完了(`gas/setup.gs`) |
| **Step 1** | 通知の自動化(月初のチェック行自動生成、メールリマインド、更新日アラート) | **`gas/step1_notifications.gs`** |
| **Step 2** | ユーザー数のAPI自動取得(Google Workspace → Slack) | 完了: `gas/step2_workspace.gs` / `gas/step2_slack.gs`(Claude APIは手動継続 — 下記参照) |
| Step 3 | 在籍者マスタとの突合・前月比差分の自動検知 | 未着手 |

## Step 0: セットアップスクリプトの実行手順

### 1. Apps Scriptを開く

管理スプレッドシートを開き、メニューの **拡張機能 > Apps Script** を選択します。

### 2. スクリプトを貼り付ける

- エディタに表示される `コード.gs` の中身をすべて削除し、[`gas/setup.gs`](gas/setup.gs) の内容を貼り付けて保存します。
- (任意)エディタ左の「プロジェクトの設定」→「タイムゾーン」が `Asia/Tokyo` になっているか確認してください。

### 3. 実行する

- エディタ上部の関数選択で **`setupSheets`** を選び、「実行」をクリックします。
- 初回は権限の承認画面が出るので、自分のアカウントで承認します(このスクリプトが触るのはこのスプレッドシートのみです)。

### 4. 実行後に確認すること

実行が完了すると、既存シートはそのままに以下の5シートが追加されます。

| シート | 役割 |
|---|---|
| ダッシュボード | 月額費用合計・カテゴリ別小計、更新期限60日以内の契約、今月の未チェック、前月比変動(すべて数式による自動集計) |
| ツールマスタ | 契約情報のマスタ。1プラン1行(Figma・Claude・ChatGPTは複数行に分解)。単価×数量×為替レートで月額円換算を自動計算 |
| 月次チェックログ | 毎月のチェック結果を上書きせず行追加で記録。2026-07分を現行シートから移行済み |
| 在籍者マスタ | 退職者突合用(現時点は空。Step 2でGoogle Workspaceから自動取得予定) |
| 設定 | 為替レート(GOOGLEFINANCEで自動取得、手動上書き可) |

**黄色のセル(要確認)** は、料金・人数が「不明」と確認済みの箇所です(セルのメモ参照)。判明したタイミングで入力してください。

- Vercel: 有料シート数
- マネフォ給与: 基本料金(従量単価¥300/人のみ計上)
- マネフォ経費・Pay・クラウド: 料金

### 運用ルール

- **プラン変更時**: ツールマスタの単価・数量セルを直すだけ。月額換算は自動で追従します。
- **単価はすべて「月額換算」で入力**(年額契約は12で割った値。例: codemagic $3,990/年 → 332.5)。
- **月次チェック**: 月次チェックログに当月の行を追加して記録(上書きしない)。Step 1でこの行生成を自動化予定。
- **解約時**: マスタの行は削除せず、ステータスを「解約済」に変更(月額集計から自動的に除外され、行がグレー表示になります)。
- **旧シート**: 数ヶ月並行運用して問題なければ手動でアーカイブ(削除またはシート名に「旧」を付ける)してください。

### 再実行について

同名シートが存在する場合、スクリプトは**何もせずエラーで中断**します(誤って上書きしない設計)。作り直したい場合は、追加された5シートを削除してから再実行してください。

## Step 1: 通知自動化の導入手順

Step 0のセットアップ完了後に導入します。通知は**メール**で、「やることがあるときだけ」届く設計です(外部サービスの設定は不要)。

### 1. スクリプトを追加する

1. スプレッドシートの **拡張機能 > Apps Script** を開く(setup.gsと同じプロジェクト)
2. エディタ左の「ファイル」の **+ > スクリプト** で新しいファイル(名前: `step1_notifications`)を作成し、[`gas/step1_notifications.gs`](gas/step1_notifications.gs) の内容を貼り付けて保存

### 2. 動作確認とトリガー登録

1. 関数 **`testEmailNotification`** を実行 → 初回は権限承認 → 自分宛にテストメールが届くことを確認
2. 関数 **`setupTriggers`** を実行 → 以下の2つの定期実行が登録される(再実行しても重複しない)

| タイミング | 動作 |
|---|---|
| 毎月1日 9時台 | 当月のチェック行を自動生成(行構成は前月から引き継ぎ・通知なし)。更新日が60日以内の契約が**あるときだけ**メールでアラート |
| 毎月8日 9時台 | 「未確認」が**残っているときだけ**メールでリマインド(全部済みなら何も来ない) |

3. 今月分の行をすぐ作りたい場合は **`runMonthlyStart`** を手動実行(当月分が既にあれば何もしない)

### 補足

- 送信先はトリガーを登録した人のメールアドレス。変えたい・複数人に送りたい場合は、プロジェクトの設定 > スクリプト プロパティに `NOTIFY_EMAIL` を追加(カンマ区切りで複数指定可)
- チームのチャンネルに流したくなったらSlack通知版に戻すこともできます(Git履歴の過去バージョンに実装あり)

## Step 2-1: Google Workspaceユーザー数の自動取得

Step 1の導入完了後に追加します。**Google Workspaceの管理者権限があるアカウント**で設定・実行してください。

### 1. Admin SDKを有効にする

1. Apps Scriptエディタ左の **サービス(+)** をクリック
2. **Admin SDK Directory API** を選んで「追加」(識別子はデフォルトの `AdminDirectory` のまま)

### 2. スクリプトを追加する

- 新しいファイル(名前: `step2_workspace`)を作成し、[`gas/step2_workspace.gs`](gas/step2_workspace.gs) の内容を貼り付けて保存

### 3. 動作確認とトリガー登録

1. 関数 **`syncWorkspaceUsers`** を実行(初回は権限承認あり)。以下が行われます:
   - 月次チェックログの当月「GoogleWorkspace」行にアクティブユーザー数を自動記入(**結果のOK判定は従来どおり人間が行う**)
   - 停止中アカウントの人数と、在籍者マスタで「在籍」なのにWorkspaceにいないメールを同行のメモ列に記録
   - 在籍者マスタに全ユーザーを反映(新規は行追加、停止中は「退職」に更新。氏名・区分などの手動編集は上書きしない)
2. 在籍者マスタに追加された行の **区分(社員/業務委託)を手動で埋める**(初回のみ)
3. 関数 **`setupStep2Triggers`** を実行 → 毎月1日10時台(Step 1の行生成の後)に自動実行

### 補足

- Workspaceに存在しない「在籍」メンバーは自動で退職扱いにしません(業務委託などWorkspace未付与のケースがあるため)。ログのメモ列に記録するだけなので、該当者は在籍者マスタの備考に「Workspace対象外」などとメモしておいてください。
- カシェイ側のGoogle Workspaceは別組織のため対象外です(従来どおり)。

## Step 2-2: Slackユーザー数の自動取得

### 1. Slackアプリを作成してBotトークンを発行する

1. https://api.slack.com/apps を開き、**Create New App > From scratch** を選択
2. アプリ名(例: `SaaS管理bot`)を入力し、自社のワークスペースを選んで作成
3. 左メニューの **OAuth & Permissions** を開き、「Scopes > Bot Token Scopes」に以下の2つを追加:
   - `users:read`
   - `users:read.email`
4. 同じページ上部の **Install to Workspace** をクリックして承認
5. 表示される **Bot User OAuth Token**(`xoxb-` で始まる)をコピー

### 2. トークンを設定してスクリプトを追加する

1. Apps Scriptエディタの **プロジェクトの設定(歯車) > スクリプト プロパティ** に追加:
   - プロパティ名: `SLACK_BOT_TOKEN`、値: コピーしたトークン
   - ※ トークンはコードに直書きしない
2. 新しいファイル(名前: `step2_slack`)を作成し、[`gas/step2_slack.gs`](gas/step2_slack.gs) の内容を貼り付けて保存

### 3. 動作確認とトリガー登録

1. 関数 **`syncSlackUsers`** を実行(初回は外部接続の権限承認あり)。以下が行われます:
   - 全ユーザーを「管理者 / メンバー / マルチchゲスト / シングルchゲスト」に自動分類し、月次チェックログの当月のSlack 4行に人数を記入
   - 管理者・メンバーのうち**在籍者マスタで「在籍」になっていない人**をメモ列に記録(退職者残りの検知)
   - ゲスト2行のメモには名前一覧を記録(不要なゲストの目視チェック用)
2. 関数 **`setupSlackSyncTrigger`** を実行 → 毎月1日10時台に自動実行

### 補足

- Bot・解除済みアカウントは人数に含めません。
- 在籍者マスタとの突合はメールアドレスで行うため、Slackのプロフィールにメールが入っていない人は「要確認」として出ます。
- アプリの作成・インストールにワークスペースの管理者承認が必要な場合があります。

## Step 2-3: Claude API — 手動継続

Anthropic Admin API(コスト・APIキー・メンバーの自動取得)には**組織のadminロールで発行するAdmin APIキー**が必要ですが、現在adminロールを持っていないため導入を見送り、「Claude API」行は従来どおり手動チェックを継続します。

**手動チェックのおすすめ運用**: Consoleの [Usage](https://platform.claude.com/usage) / [Cost](https://platform.claude.com/cost) ページで前月コストを確認し、月次チェックログの「Claude API」行の**数量列に前月コスト(USD)を数値で入力**してください。数値で入れておくと前月比の増減が自動計算され、ダッシュボードの変動検知にも載ります。

将来adminロール(またはAdmin APIキー)が用意できた場合は、`gas/step2_claude.gs` を導入すれば自動化できます(手順はファイル冒頭のコメント参照: スクリプトプロパティ `ANTHROPIC_ADMIN_KEY` にキーを設定 → `syncClaudeApi` 実行 → `setupClaudeSyncTrigger` でトリガー登録)。

## ディレクトリ構成

```
gas/
  setup.gs                # Step 0: シート構成セットアップ(移行データ込み)
  step1_notifications.gs  # Step 1: 月初の行自動生成+メール通知
  step2_workspace.gs      # Step 2-1: Google Workspaceユーザー数の自動取得
  step2_slack.gs          # Step 2-2: Slackユーザー数の自動取得(4区分)
  step2_claude.gs         # Step 2-3: Claude APIのコスト・キー・メンバー自動取得
  appsscript.json         # GASマニフェスト(AdminDirectory有効化済み)
```
